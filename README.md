# Sales Data Warehouse & ETL Pipeline

A hands-on **SQL Server + SSIS ETL project** that loads CSV sales data into a dimensional data warehouse using staging tables, transformations, Lookup transformations, surrogate keys, and validation queries.

## Tech Stack

- **Database:** Microsoft SQL Server
- **ETL:** SQL Server Integration Services (SSIS)
- **Language:** T-SQL
- **Source:** CSV files
- **Model:** Star Schema

## ETL Architecture

```text
CSV Source Files
      ↓
SSIS Flat File Source
      ↓
Data Conversion
      ↓
Staging Tables
      ↓
Customer Lookup ──→ CustomerKey
      ↓
Product Lookup  ──→ ProductKey
      ↓
Date Lookup     ──→ DateKey
      ↓
FactSales
```

## Warehouse Design

The project uses a dimensional model with:

- `DimCustomer` — customer dimension with surrogate `CustomerKey`
- `DimProduct` — product dimension with surrogate `ProductKey`
- `DimDate` — date dimension with `DateKey`
- `FactSales` — sales fact table containing measures and dimension keys

## SSIS Data Flow

### Customer and Product Loading

- Reads customer, product, and sales CSV files.
- Performs data type conversion where required.
- Loads staging tables.
- Uses Lookup transformations to retrieve surrogate keys from dimension tables.
- Loads the resulting keys into `FactSales`.

### Fact Sales Loading

The final fact load maps:

| Source/Input | Destination |
|---|---|
| `SalesID` | `SalesID` |
| `DateKey` | `DateKey` |
| `CustomerKey` | `CustomerKey` |
| `ProductKey` | `ProductKey` |
| `Quantity` | `Quantity` |
| `SalesAmount` | `SalesAmount` |

`SalesKey` is generated by the destination table, while `LoadDate` is handled by the warehouse design.

## Validation

The project includes SQL validation queries for:

- Staging row counts
- Dimension row counts
- Fact table row counts
- Distinct customer, product, and date keys
- Duplicate checks
- Data validation after ETL execution

The source data contains **8 customers, 6 products, and 16 sales transactions**. A fresh fact-table load should therefore contain **16 rows**. If the package is executed again without clearing the fact table, rows can be appended and the count can become higher.

## How to Run

1. Install SQL Server, SSMS, and Visual Studio with SSIS support.
2. Execute `02_SQL Scripts/01_Create_Database.sql` in SQL Server.
3. Open the SSIS project in `03_SSIS Design/SalesETL.dtproj`.
4. Configure the Flat File Connection Managers to point to the CSV files in `01_Source Data`.
5. Execute the SSIS data flows in the required order:
   - `DFT_Load_Customers`
   - `DFT_Load_Products`
   - `DFT_Load_Sales`
   - `DFT_Load_FactSales`
6. Execute `02_SQL Scripts/03_Validation_Queries.sql` to verify the results.
